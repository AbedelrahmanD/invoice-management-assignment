# Invoice Management — .NET Senior Developer Test

A Blazor Server application for managing invoices and their line items. The application is built with .NET 10, Entity Framework Core, and SQLite.

## Tech Stack

* .NET 10 / C#
* Blazor Server with Interactive Server render mode
* Entity Framework Core
* SQLite
* Bootstrap 5
* Bootstrap Icons

## Prerequisites

* .NET 10 SDK

That's all that's required. There is no separate database server or Docker setup. SQLite is used as a local database and the database file is included in the repository.

## Running the Application

```bash
git clone https://github.com/AbedelrahmanD/invoice-management-assignment
cd invoice-management-assignment/InvoiceManagement
dotnet run
```

Once the application is running, open:

**[http://localhost:5245/](http://localhost:5245/)**

The repository includes `Db/invoices.db` with a sample invoice, so the invoice list will have data when the application starts for the first time.

`Database.Migrate()` runs during startup to make sure the database schema is up to date. If the database file is deleted, the application will create it again on startup.

## Managing Invoices

From the invoice list:

1. Click **New** to create an invoice, or use the edit button on an existing invoice.
2. Enter the customer name and invoice date.
3. Use **Add Line** to add invoice items. Each item has a name, quantity, and price.
4. Line totals and the invoice total are updated as the values change.
5. Click **Create** or **Update** to save the invoice.
6. An existing invoice can be deleted from the edit screen. A confirmation is required before deleting.

Deleting an invoice also removes its line items.

## Design Decisions

### Domain Model

The assignment limits the number of fields on the models, so the models are kept intentionally small.

`Invoice` contains:

* `Id`
* `Number`
* `CustomerName`
* `Date`
* `TotalAmount`
* `Items`

`Items` is the navigation collection and isn't a scalar database field.

`InvoiceItem` contains:

* `Id`
* `Name`
* `Quantity`
* `Price`
* `InvoiceId`
* `LineTotal`

`LineTotal` is marked with `[NotMapped]` and is calculated from `Quantity * Price`, so it isn't stored in the database.

There is no navigation property back from `InvoiceItem` to `Invoice`. It isn't needed by the current application and keeps the model simpler.

### SQLite

The SQLite database is committed to the repository with a sample invoice.

This keeps the setup simple: clone the repository, run the application, and the data is already there. No external database service is required.

### DbContext Factory

The application uses `IDbContextFactory<AppDbContext>` rather than keeping a `DbContext` around for the lifetime of a Blazor circuit.

Blazor Server circuits can remain active for a long time, and multiple operations can potentially run against the same circuit. Using the factory gives each operation its own short-lived `DbContext` and avoids concurrency issues with a shared context.

### Service Layer

The UI doesn't access Entity Framework directly.

Invoice operations go through `IInvoiceService`, which keeps the Razor components focused on UI concerns and keeps the data/business logic in one place.

### Updating Line Items

When an invoice is updated, the existing line items are replaced with the current items from the form.

The delete/add operations are wrapped in a transaction so the update either completes successfully or is rolled back.

### Invoice Total

`TotalAmount` is calculated on the server from the invoice line items whenever the invoice is saved.

The total isn't editable from the UI. This keeps the stored invoice total consistent with its line items.

### Invoice Number

Invoice numbers are generated by the service using the current maximum number plus one.

There is also a unique index on the invoice number. If two requests happen to generate the same number concurrently, the database will reject the duplicate.

Full concurrency handling isn't implemented because it isn't required for the scope of this test.

### Flash Messages

`FlashMessageService` is scoped to the Blazor circuit and is used to display messages such as successful saves after navigating back to the invoice list.

This also keeps messages isolated between users.

### Validation

Validation is handled at both the UI and service levels.

* `[Required]` and `[Range]` attributes are used on the models.
* `<DataAnnotationsValidator />` handles the standard form validation.
* `InputNumber` fields have parsing error messages for invalid numeric input.
* An invoice must contain at least one line item before it can be saved.

The line-item requirement is enforced in the service layer rather than relying only on the UI.
